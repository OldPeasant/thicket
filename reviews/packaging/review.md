## P2 Medium

- [ ] **CR-1 | macOS `identity: null` ships a modified, unsigned bundle; Apple Silicon users likely get "damaged" instead of a bypassable Gatekeeper warning**
    - File: `apps/desktop/electron-builder.yml:53`
    - Category: Integration
    - Problem: `identity: null` makes electron-builder skip code signing entirely (`MacTargetHelper.handleNullIdentity`, and `macOptions.d.ts`: "`null`: skip signing entirely. `"-"`: opt in to ad-hoc signing"). electron-builder then renames the executable, rewrites `Info.plist` and adds `app.asar`, so the Electron bundle's original signature/seal no longer matches. On Apple Silicon, quarantined downloads of such bundles are commonly rejected as "is damaged and can't be opened" (no Open Anyway path; users need `xattr -cr`), whereas an ad-hoc-signed bundle gets the normal unidentified-developer flow. Could not be verified here (no macOS; criterion 3 is skipped for that reason), so this is a configuration risk, not an observed failure.
    - Why it matters: SPEC "Release" requires unsigned dmg for arm64 and x64 and a README that explains the Gatekeeper warning; a "damaged" message is not the warning the README can explain, and the arm64 dmg would be unusable for most users.
    - Suggested fix: use `identity: '-'` (ad-hoc) with the existing `hardenedRuntime: false`, and have the macOS installer smoke test (`installer-smoke` / `release-ci`) launch the quarantined dmg on an arm64 runner. If kept as-is, record it as an assumption so release-ci verifies it.

## P3 Low

- [ ] **CR-2 | Workspace `dist` / `dist:dir` can package a missing or stale renderer without failing**
    - File: `apps/desktop/package.json:28-29`, `apps/desktop/electron-builder.yml:22-26`
    - Category: Quality
    - Problem: only the root `dist` script builds `packages/renderer` first. `npm run dist -w apps/desktop` and `dist:dir` do not, and electron-builder only logs a warning when an extraResources source is missing (`fileMatcher.js` `copyFiles`: `log.warn(... "file source doesn't exist"); return`). The result is an app that starts and shows a blank 404 window, or ships an outdated renderer.
    - Why it matters: an easy way to produce and smoke-test the wrong artifact locally or in a future CI job that calls the workspace script.
    - Suggested fix: either build the renderer in the workspace scripts too, or fail fast in a tiny pre-step if `../../packages/renderer/dist/index.html` is missing; document `dist:dir` next to `dist` in ARCHITECTURE.

- [ ] **CR-3 | Packaged app keeps default Electron fuses and dev-only env hooks**
    - File: `apps/desktop/electron-builder.yml` (no `electronFuses`), `apps/desktop/src/main/index.ts:49-55`
    - Category: Security
    - Problem: no `electronFuses` block, so the shipped binary still honours `ELECTRON_RUN_AS_NODE`, `NODE_OPTIONS`, and does not enforce `onlyLoadAppFromAsar` / embedded asar integrity. The packaged app also still honours `THICKET_DEV_SERVER` (loads an arbitrary http origin with the preload bridge and a CSP that allows that origin) and `THICKET_RENDERER_DIR`. Not required by SPEC, and environment control already implies local code execution, so impact is limited; it is defence in depth that is cheapest to add now.
    - Why it matters: standard Electron hardening for distributed builds; reduces the app's use as a signed/trusted Node launcher once signing arrives.
    - Suggested fix: add `electronFuses` with `runAsNode: false`, `enableNodeOptionsEnvironmentVariable: false`, `onlyLoadAppFromAsar: true`, `enableEmbeddedAsarIntegrityValidation: true` (mac/win), `enableCookieEncryption: true`; keep `enableNodeCliInspectArguments` on only while the Playwright-based smoke test needs it (Playwright attaches via `--inspect`). Consider ignoring `THICKET_DEV_SERVER` when `app.isPackaged`. Defer to a follow-up task if preferred.

- [ ] **CR-4 | Smoke script: launch failure bypasses cleanup and diagnostics**
    - File: `apps/desktop/scripts/smoke-packaged.mjs:24-41`
    - Category: Quality
    - Problem: `_electron.launch(...)` runs before the `try`, so a launch failure (wrong path, missing FUSE/sandbox, crash before the inspector attaches) exits via an unhandled rejection: the `thicket-smoke-*` temp dir is left behind and the `smoke: FAILED` line and captured output are never printed. Output listeners are also attached only after launch, so early startup lines are lost.
    - Why it matters: this script is the documented packaged-build check and will likely be reused by `installer-smoke`; when it fails, it should say why.
    - Suggested fix: move the launch inside the `try` (guard `app?.close()` in `finally`), and pass the error to the same failure path.
